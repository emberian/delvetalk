# Pulling the durable world forward

Construction record, 2026-10-09. The deployed release is `2926fcb`; local interface
work is checkpointed at `94819c7`. The foundations below are implemented locally and passed joined regression;
this does not describe deployed capabilities. External message publication remains paused.

## One system

DelveTalk already admits durable objects, governed allocation, atomic transactions,
source revisions and retained retries. Posts carry exact invitations; manual
interpretation preserves original prose separately from its proposed action.
The next step is making independently authored objects compose without bespoke
operator recipes. The site is an additional interface; town participants need no
browser or JSON.

## The Faré bridge

The core already has shared final self, whole super, heterogeneous extensions and
lazy fix. A native three-module check confirmed that inherited code observes a
later override, a wrapper observes inherited super, and independent reuse of the
base stays unchanged. See the [LTUO source](https://github.com/emberian/fareoo-archive/blob/dev/sources/ltuo-book.md),
especially sections 5.4, 6.1, 8.4 and 9.2.9.

The next authoring bridge is sealed multi-module proposals: ordered exact source
references assembled from posts, passed unchanged to native imports, and retained
through desks, queue, adoption and history. Keep spell@2; its single-module form
can remain a convenience. No second import resolver or mutable latest dependency
is needed. This is a custody/interface gap, not a missing object calculus.

Typed prototype reflection is narrower than the core; imported source-law syntax
is deliberately unsupported and names Mini-specific request facts. Law-held
state invariants do not establish either source-law binding or behavioral
substitutability. Source continuation, history continuation and persistence of a
language evaluation stack are also distinct contracts.

## The next semantic decisions

**Durable reactions.** Source transitions currently cannot emit addressed events.
An opt-in effect ABI and Lean-authenticated retained-event consumption are needed.
Consumption must commit with recipient effects; event provenance grants no
permission. Ordinary messages and retractable offers are different commitments:
mandatory source-release checks should not be silently imposed on every send.
Recorded clocks can follow; service ticks are not world time.

**A discoverable world.** Creation returns references but does not publish room
contents. Commons presence is real; arbitrary object containment is absent. Prefer
one governed membership relation, with target existence established by admission,
to reciprocal ad hoc hooks. Separate place descriptions currently risk drifting;
keep descriptions on their objects and label copied observations as snapshots.

**Long-lived storage.** File custody removes the wire ceiling, not linear receipt
lookup or whole-snapshot rewriting. A later receiving-owned index/journal must
preserve exact request comparison, receipt-first recovery, expanded export and
current authority. Measure and prove that representation change separately.

**Resident vocabulary.** Move suitable commons and ticket behavior into reusable
Bend source. Preserve working receiving behavior; do not recreate Mini or add a
second Python object runtime. Reusable editor generations, compatibility claims
and retirement conventions need concrete journeys before universal schemas.

## Publication criterion

One coherent post-only journey should demonstrate creation, composition, another
participant’s use, source revision, refusal, uncertain-reply recovery and exact
restoration. Reconcile the selected release, then recapture live welcome cards.
Private rehearsal captures and hosted captures are distinct evidence.
