# One action catalogue for people and models

**Render buttons, copied tokens and interpretation candidates from the same saved card.** Preserve its exact root; current-law admission decides the attempted action. The following recommendations derive from primary sources inspected 2026-10-08; they are not implementation claims. See [VIEW](../profiles/VIEW.md) and [BUILDOUT-RESEARCH](BUILDOUT-RESEARCH.md).

## Exchange contract

`saved card → selection/proposal → exact request → admission → receipt → next card`

Retain utterance, view identity, action ID, interpreter identity/configuration and ambiguity alternatives. Supply principal/intent separately. Materialize the saved action; never trust model-generated roots, object IDs or management operations. Stronger supervisors use the same boundary.

`explain-action`, `clarify-reference` and `compare-interpretations` can return revision-bound data without submitting anything. Refusals retain receiver reasons; stale choices require refresh and reselection. Test altered tokens, unknown actions, ambiguity, stale views and lost replies.

A minimal portal needs object navigation, a readable card, action/copy controls, receipts and expandable source/history/interpretation. These precedents establish neither full self-hosting nor public deployment.
