Reviewed `392c1f98` and the preceding day’s scoped merges. Validation used source tracing and read-only, in-memory probes.

Ranked defects:

1. **P1 — An unauthenticated request can block all service authentication.** [transport/serviceauth.py:117](transport/serviceauth.py:117), [transport/http.py:907](transport/http.py:907). A well-shaped JWT naming an attacker-controlled `did:web` reaches document fetching while holding the verifier’s global lock, before rate limiting. A stalled HTTPS response therefore blocks even valid tokens whose issuer documents are already cached; this was reproduced. Socket timeouts also permit indefinitely trickling responses. **Fix:** fetch outside the global admission lock, use per-issuer coordination, impose an absolute fetch deadline, and rate-limit before resolution.

2. **P1 — Closing firehose connections have an unlimited input buffer.** [transport/firehose.py:419](transport/firehose.py:419), [transport/firehose.py:489](transport/firehose.py:489). A subscriber stops reading until outgoing data blocks, then sends an invalid frame. `finish()` sets `closing`, but read interest remains enabled; subsequent input accumulates while parsing and heartbeat expiry both skip closing connections. The subscriber can exhaust the front’s memory. Twenty reads retained 1,310,720 bytes without processing or rejection. **Fix:** disable read interest and clear inbound data when closing; enforce a short close deadline.

3. **P1 — JWT replay protection disappears on restart.** [transport/serviceauth.py:75](transport/serviceauth.py:75), [transport/serviceauth.py:145](transport/serviceauth.py:145). A token accepted immediately before a front restart is accepted again afterward, until `exp`; reproduced with two verifier instances. Because the token binds the method rather than the body, a captured token can authorize a different call and intent after restart. **Fix:** atomically retain consumed `(audience, issuer, jti)` values durably until expiry. The [service-auth specification](https://atproto.com/specs/xrpc#inter-service-authentication-jwt) requires nonce-based replay prevention.

4. **P1 — A malicious PDS can consume another resident’s request URI.** [transport/requests.py:194](transport/requests.py:194), [transport/requests.py:222](transport/requests.py:222). Repository A’s listing can supply `at://B/online.fg-goose.gsb.request/<rkey>`. Verification proves **A’s** record at that rkey, but insertion retains the listing’s **B URI**. Since observations are unique by URI, B’s actual request is subsequently skipped as seen; the answer also occupies B’s answer key. This was reproduced using a valid signed A proof. **Fix:** validate the listing URI’s repository and collection, and construct the observation URI from the proven DID, collection, and validated rkey.

5. **P1 — XRPC retries permanently retain transient refusals and suspensions.** [transport/http.py:419](transport/http.py:419), [transport/bridge.py:344](transport/bridge.py:344). After a `quota` refusal, `Front.turn` returns its receipt without invoking the host again—even after the quota clears. After suspension, the public answer saves that entry’s hash; following settlement, retries continue reading the old suspended entry, and the writer preserves it. Both paths were reproduced. **Fix:** resolve the current receipt by identity through the host, distinguish retryable/intermediate receipts from terminal ones, and replace suspended answers when settlement arrives.

6. **P1 — Different worlds produce different repositories under the same hosted DID.** [transport/hosted.py:40](transport/hosted.py:40), [transport/hosted.py:131](transport/hosted.py:131). Town and `ring` fronts sharing the configured origin both name Robin `did:web:robin.guest.<origin>`, while using separate snapshots and different world keys. Consequently the same DID has incompatible records, commits, and verification keys depending on which front answers. Canonical DID resolution reaches only one of them. **Fix:** keep hosted accounts origin-wide, with one shared snapshot store and the town key; other-world fronts should route to that account repository.

7. **P2 — Record requests addressed to another world’s advertised DID never run.** [transport/requests.py:99](transport/requests.py:99). For `--world ring`, the front advertises `did:web:ring.<origin>`, but the poller initializes its service as `did:web:<origin>`. A correctly addressed ring request is retained as “addressed to another service.” The mismatch was reproduced. **Fix:** pass `st.world` to `world_did`.

8. **P2 — Repository JSON routes advertise records absent from the repository.** [transport/repo.py:313](transport/repo.py:313), [transport/repo.py:482](transport/repo.py:482). `describeRepo`, `getRecord`, and `listRecords` advertise card/page/index/answer records under the world DID, but `getRepo` contains only entries and `sync.getRecord` rejects those collections. A client obtains `index/self` with HTTP 200, then cannot recover or prove it from that repository; reproduced. These paths contradict the [repository model](https://atproto.com/specs/repository). **Fix:** serve these live values through projection queries until they actually join the signed MST; remove them from repository collection advertising and correct REPO/ATPROTO’s canonical-record claims.

9. **P2 — Signed reads retain every historical event CAR, including with firehose disabled.** [transport/repo.py:181](transport/repo.py:181), [transport/repo.py:186](transport/repo.py:186). Every height constructs an inversion-complete CAR and retains it forever in `heights`. Firehose compaction does not release this cache. A 20,000-entry probe retained 60,910,595 bytes of CARs alone; continued ordinary journal growth can exceed the front’s 512 MiB deployment limit well before journal capacity. **Fix:** construct CARs only for events awaiting production, discard them after durable logging, and bound pending event bytes.

10. **P2 — Ordinary call fields containing `tag` are interpreted as wire-codec instructions.** [transport/http.py:128](transport/http.py:128), [transport/host.py:192](transport/host.py:192). The lexicon accepts ordinary JSON fields such as `{"tag":"blue","text":"rain"}`, but `typed()` forwards that dictionary unchanged instead of producing a record. The host receives an unknown Data discriminator and rejects the call; nested dictionaries have the same collision. **Fix:** use an unambiguous conversion for plain procedure fields; reserve explicit typed Data for a separately identified input form.
