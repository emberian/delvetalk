# The environment speaks through its objects

**Decision.** Posts and the web portal present the same authored encounter. An
inhabitant should learn what is here, what a contribution would mean, what remains
undecided and what happened. They should not need knowledge of compiler profiles,
internal operation names, raw hashes or a special operator command to discover an
offered action. Technical inspection remains available separately.

Current source views really own descriptions and availability. The missing piece
is coherent interaction around those values. The audit found normal Town capture
omitting Editor source offers while the portal included them: an editable object
could say “look only.” A consumer fix now includes offers in ordinary capture;
this repairs discovery, not the underlying Python preparation interpreter.
A test beginning with an operator who knows a hidden `capture-offer` key does
not establish a usable town interface.

## One encounter, several renderings

An authored encounter identifies its subject, explains its current situation,
offers contributions and names related things. An invitation includes readable
words, a concrete example, affected relationships, required choices and whether
it acts now or sends a request. It can explain a blocked prerequisite instead of
simply disappearing. Source owns those explanations; the host adds actual receipt
diagnostics without inventing world policy. Visibility still grants no authority.

Use one capture/preparation contract for ordinary actions and composed actions.
Town text, browser controls and agent-readable structure render the same captured
meaning. Renderers can truncate presentation to a platform budget and expose a
continuation, but cannot silently drop an action category or choose different
targets. Internal IDs and exact roots remain retained beneath readable local names.

## Incomplete language is a first-class contribution

“Make that moth sing when released” is a useful beginning. A source conversation
object can retain the selected offer, supplied arguments, unresolved references
and remaining questions. An operator interprets the original utterance explicitly;
Bend decides what information the chosen operation still needs. No general NLP
engine is required, and the operator's interpretation is not a proof of intent.

If two moths fit, offer those actual references and ask which. Preserve the answer's
captured alternatives. If they change, explain the changed choice; do not let “the
other one” silently refer to a new object. Two participants' partial contributions
remain distinct unless source explicitly joins them. Incomplete work produces no
world effect merely because its prose sounds imperative.

Once complete, source prepares the typed turn described in
[composition](COMPOSITION.md). Show the selected meaning and consequence at the
appropriate interaction point. Preserve ordinary literal replies for agents that
prefer selecting tokens directly. The same operation should accept either route;
an extra mandatory syntax is not a substitute for designing the encounter.

## Programming should feel like contributing

An inhabitant should be able to inspect a working contribution, choose parameters,
derive a variation, try examples, invite review, adopt it and see another inhabitant
use it. Offer exact source and its selected dependencies through that process.
Reusable modules, prototypes and specifications are the actual implementation,
not metaphors applied to a Python workshop manager.

Create reusable source contributions alongside the low-level compiler workbench:
a chorus, an agreement, a mailbox policy, a scene handler or a room admission rule.
Each has an understandable effect and an explicit reuse boundary. No mutable
ambient import search is needed; selecting a contribution selects its revision.
The editor's own questions, review logic and preparation are also inspectable
source which can be improved through governed editing.

## Parallel work and acceptance

Normal town/portal encounter parity is an immediate consumer fix. Source partial
intentions and reference clarification can be built on current typed state.
Reusable contribution objects and authored explanations are independent source
work. Native preparation removes the Python descriptor interpreter while these
surfaces mature; it should not postpone them.

Use unfamiliar participants: can one discover an invitation from an ordinary
post, answer an ambiguity, reuse another's behavior and understand a refusal?
Compare the selected meanings across town and portal. Keep exact source/result
recovery checks, but do not mistake those checks for evidence that the interaction
is comprehensible. Do not require a single giant showcase to declare progress.
