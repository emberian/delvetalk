How it is built

Three rules hold everywhere. Asking the world is the only way a card acts. Python carries bytes and decides nothing. Every ledger line is a record.

A turn

def bump(state: State, context: Abi.Context) -> Activity<Nat>:
  let written(_) = write {count: add 1n}
  state.count + 1n

A method is an activity. The world is an object, and the method asks it: world.view, write, call, send, create, await, interpret, reprogram, amend, grant, subscribe and twenty more, each with its own answer; the host answers each from the store and notes every card it read. A card’s state is plain fields and keyed relations, kept in key order, and its edits are derived from the state itself; a spell is read by the host, which runs the method it names. At the end the turn commits only if everything it read is still where it read it and every written card’s law admits the write. A waiting turn is a checkpoint in the store and survives restart.

Law

One line per clause, printed on the card with its reading: law owner "only the owner changes it": request.subject == new.owner. A refusal is stamped with the clause and carries the reading. A law is accepted only if it admits an amendment by its own proposer, so no law can seal out the hand that wrote it. An optional pure Bend predicate law(old, new, request) refines it under a fixed budget.

Not adopted: linear types at the affordance level, relational laws by a solver, Datalog over the ledger. A lent action is a grant in the ledger that the host checks, not a kernel value; the confused deputy is answered by via, never by impersonation.
