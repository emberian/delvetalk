# An ordinary root directory

`Directory.obend` renders a bounded recursive list of configured doors as one
structured `Document`. Its plain reading is `Document.plain` of that same value.
Browser references bind only to matching source children; the inline choice
binds only to the actual captured source invitation. No host router knows these
door names.

`GSBWelcome.obend` supplies the six opening descriptions as ordinary configuration.
They initially say **not open** and have no targets. An authorized steward uses
`setDoor` to connect real objects, change the wording, or hide an unavailable entry
with `show=false`. Available doors require a nonempty target. The configured
capacity may be smaller than the library's eight-door maximum. Labels, descriptions,
examples, introduction and closing belong to revisable Bend source/data.

A participant can follow a reference to its independently governed encounter, or
answer the captured `choose` invitation with `{door,original}`. Source asks which
door when it is missing, checks the configured enabled reference, requires its
current captured observation, and prepares an ordinary native turn. That turn
returns the reference and original words under the participant's actual identity.
It does not execute a target operation or confer target authority. Current owner
and selected-target roots remain exact; old cards are never refreshed silently.

Natural replies are manually interpreted first. This package supplies no global
verb grammar or hidden model request. Private studio access remains an authenticated
service relationship; putting “studio” on a shared page creates no private access.

Supply ordered modules `Abi`, `Preparation`, `Encounter`, `Document`, `Directory`,
`GSBWelcome` to `objective-bend-spell@3`. The first three come from
`world/lib/prelude`, Document from `world/lib/document`, and the last two from this
directory. Use the compiled receiver. Grant `setDoor` only to directory editors;
grant `choose` to the intended participants separately.

The tests install a real source garden, configure its actual reference, and use
Portal/Town capture plus native preparation/admission. Unavailable doors remain
text or are omitted. The local example reading is a candidate, not a deployed
card or publication. No generated executable JSON twin is needed.

## Fresh sessions from an original post

The Welcome post points people to summon a fresh session by tagging
`@livedelvetalk.delve.town` **and** `#gsb`. Those markers support discovery; an
operator verifies and facilitates the original post before invoking this package.
The root document is the session response/browser entry, not a permanent action
capture embedded in Welcome.

`SessionFactory.obend` accepts `{author,originUri,originCid}` under its current
operator law. Its source preparation captures the configured open targets, the
factory root and the next child's absence. One native turn allocates `session-N`,
opens its source directory and applies the configured door list. Source chooses the
name, configuration and grants. The participant receives `choose`; the operator
receives configuration and management rights. The 64-session allocation bound is
explicit. A session's source transitions preserve its original author/URI/CID;
visitor contributions retain their own actual native principal independently.

The child program starts compact; source `begin` constructs its six descriptions
inside the allocation transaction. This avoids wrapping a recursive typed initial
model inside a second recursive generic program representation. It is an ordinary
source invocation, not an alternative host constructor. A direct `make` invocation
only allocates; use the captured `prepareMake` invitation for the ready session.

`package.entry()` loads the checked session source.
`package.factory(entry, doors=[explicit door records], welcome='configured-id')`
frames configuration data for the source constructor. An empty door list leaves
all six descriptions unavailable; an empty welcome identity disables enrollment.
A configured welcome yields the source-selected result:

```text
followup = {enabled, object, offer: "enroll", fields: {did: author, proof: originCid}}
```

The physical operator captures that actual offer and retains/prepares/submits it
through the existing invitation path. Membership has its own outcome and custody;
a missing welcome, refusal or uncertain membership reply does not erase the
admitted session. `proof` is the existing Welcome ABI's evidence marker. A CID
alone is not proof of author control; verified post custody supplies that trust.
The service needs its separately configured current Welcome authority. Session
allocation grants no Garden/workshop rights by itself and cannot undo revocation.

Town intake pins the first URI to its original CID and verified author; an edited
post requires a new record key. Re-delivery or an uncertain reply recovers the
retained native request rather than opening another session. The source factory
does not independently crawl posts or treat their body as authentication.

`conformance/test_root_sessions.py` checks real allocation, independent authors,
current law, configured targets, exact retries/reopen recovery and the complete
six-door turn. `conformance/test_root_directory.py` checks source examples,
Portal/Town document binding and current target captures. Keeping document sections
as bounded sequences reduced the six-door default view to about 30,000 machine
ticks plus 2,100 bridge nodes at the existing 100,000-tick allowance; a single
constructed leaf spine and nested concatenation both cost more than the allowance.
