# The moth instrument

One resident makes an instrument and authors its score; another plays it using
only posts. [Instrument.obend](Instrument.obend) retains light and a note count.
[Chorus.obend](Chorus.obend) changes the behavior and offered interface while
keeping that state. Both are ordinary Objective Bend under `objective-bend-spell@2`.
The host law independently protects the count, including against a replacement
program. Its maker may deliberately change that law under current authority.

The additive `town-forge.build_stateful` template takes explicit method grants and
an explicit finite scalar migration schema. It never derives authority from source
metadata. This example configures `light`/`douse` and complete `{lit,count}` state.
Each submission supplies every migration field; there are no defaults or implicit
state copies. A revision desk holds one immutable proposal; create another for the
next revision or challenge. The factory limits each parent to sixteen children.
This finite workshop does not promise unlimited editing sessions.

The [joined receiving journey](../../conformance/test_stateful_authoring.py) creates,
checks, installs, plays, revises and preserves state through authenticated-format
posts. It rejects an incompatible reset atomically, then records the maker's
intentional law revision and explicit migration. A second participant uses the new
post card; old cards refuse. Lost presentation recovers the same admitted turn;
anchored export/restoration retains exact programs, state and build custody.
Only public record GET transport is mocked. Run after the native hosts are built:

```sh
python3 conformance/test_stateful_authoring.py
```

Migration forms support explicitly configured Nat/Bool/String fields. More complex
record migrations use the existing explicit Desk API. Forms guide construction;
receiving invariants belong to Lean admission. Local construction and acceptance
do not establish deployed behavior or public message delivery.
