# Source Candidate workshop

`package.py` physically carries the reviewed Candidate source and its explicit
Preparation module. The Candidate's lifecycle is defined in
`../editor/Candidate.obend`: submission, compiler reports, adoption and refusal
are source behavior. Python Desk projects typed custody fields through the native
Value codec and compiles exact retained proposal bytes. It recognizes the complete
reviewed source body, rather than trusting a protocol name or metadata claim.

`Factory.obend` reuses the Editor factory's compiler/report authority and native
allocation contract. Ordinary desks allow the maker to submit and adopt; the
configured compiler alone reports success or failure, and the configured reporters
may inspect the report. Adoption still requires current authority on the target.
The factory's source make preparation captures its root and the child's absence.

`Writing.obend` binds a Candidate, target and source language. Its source invitation
captures the selected objects; source preparation constructs the proposal,
migration and submission. `WritingFactory.obend` allocates this participant through
the same Creation/Allocation modules. A post is transported and authenticated by
the existing Clerk; no Python helper decides the workflow.

Executable packages retain the constructor entry and evaluated initial state.
Original constructor inputs are not separately recoverable from that metadata.
Source proposals, module manifests and admitted history retain their existing exact
byte custody. Current-law checks and exact retry receipts apply throughout.
