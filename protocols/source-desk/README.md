# Source Candidate workshop

`package.py` physically carries the reviewed Candidate source and its explicit
Preparation module. The Candidate's lifecycle is defined in
`../editor/Candidate.obend`: submission, compiler reports, adoption and refusal
are source behavior. Python Desk projects typed custody fields through the native
Value codec and compiles exact retained proposal bytes. It recognizes the complete
reviewed source body, rather than trusting a protocol name or metadata claim.

`Factory.obend` reuses the Editor factory's compiler/report authority and native
allocation contract. Ordinary desks allow the maker to submit. Explicitly configured reviewers join
the maker in the release grant; this relationship is separate from reporting.
The configured compiler alone reports success or failure, and the configured
reporters may inspect the report. A shared workshop configures its steward as a
reviewer. Acceptance still requires that principal’s current reprogram authority
on the actual target, so the maker’s Candidate grant cannot bypass shared
governance. The source release captures the exact Candidate, target and checked
program, and receiving rolls back the whole turn when either current law refuses.
Candidate read access is explicit for its maker, configured reviewers, compiler
and configured reporters. Reporting and acceptance remain separate invoke grants.
Factories without reviewers retain maker-only release. Editor factories retain
their separate authenticated approval sequence.
The factory's source make preparation captures its root and the child's absence.

`Writing.obend` binds a Candidate, target and source language. Its source invitation
captures the selected objects; source preparation constructs the proposal,
migration and submission. Its inspect invitation selects the target's exact captured
`resident` source table through the optional native definition argument, and
`prepareInspect` produces source Document nodes for those installed modules.
The same read grants protect source inspection and state acquisition. A retained
old definition stays exact when the target changes; revoking current read access
blocks its later acquisition. The `revise` invitation replaces a named installed
module in Bend, retaining every other captured module and the complete captured
state. This inline module proposal needs no host source file edits. Candidate
inspection shows its proposed source and authored examples through the same
Document renderer; its Check action durably requests the configured compiler.
The service consumes that source request and reports against its exact root.
Release remains a separate offered turn under current adoption authority. `WritingFactory.obend` allocates this participant through
the same Creation/Allocation modules. A post is transported and authenticated by
the existing Clerk; no Python helper decides the workflow.

Executable packages retain the constructor entry and evaluated initial state.
Original constructor inputs are not separately recoverable from that metadata.
Source proposals, module manifests and admitted history retain their existing exact
byte custody. Current-law checks and exact retry receipts apply throughout.

An existing ordinary factory with the earlier flat base state requires an explicit
state migration. The source `reviewed(base, reviewers)` constructor preserves its
compiler, reporters, child program and last-created identity while adding the
configured review relationship. Installing the new program with the old flat state
is not an upgrade, and replacing it with empty initial state loses that history.
