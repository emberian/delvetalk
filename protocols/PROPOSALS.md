# Checking source proposals

A proposal retains exact Bend source, examples, target and complete migration.
The [source desk](../profiles/DESK.md) and [compiler queue](../profiles/COMPILER-QUEUE.md)
retain its compiler report. Checking does not install an object or grant authority.

Use `objective-bend-object` and the actual source package interface described in
[source objects](../profiles/TYPED-SOURCE-OBJECTS.md) and
[module authoring](../profiles/MODULE-AUTHORING.md). Examples declare fixture
principals, inputs and expected observations. Include success and refusals for
stale roots, unauthorized callers and repeated actions. Fixture principals are
local assertions rather than authenticated external identities.

Compilation and finite examples establish their specific results. Installation
uses a separately authorized source release/adoption under current laws and exact
roots. Source, adapter closure and native executable identities remain distinct;
a source hash grants neither authority nor permission to publish.

The physical proposal runner is [propose.py](../scripts/propose.py); consult its
`--help` for retained CLI options. Current source-host cutovers are tracked in
[BACKLOG](../BACKLOG.md); use matching receiving evidence before deployment.
